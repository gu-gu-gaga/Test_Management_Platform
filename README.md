# 测试任务执行平台

模块用例库 + 产品用例库 + 任务执行 + 双轨审核的一体化测试任务执行平台。前端为纯静态页面，后端为零依赖 Node 服务（`server/`），数据统一保存在服务器，多人共用同一份数据。

平台自带账号、审批、缺陷与归档能力，**不依赖任何外部 OA 系统**：账号由 `server/data/accounts.json` 独立维护，登录页支持邮箱验证码自助注册，管理员在「设置」中统一管理账号、角色与邮箱服务。

## 目录结构

```
index.html      页面入口（按顺序加载 data.js → xlsx.js → api.js → app.js）
style.css       样式
app.js          平台逻辑（用例库 / 任务执行 / 审核 / 权限 / 统计 / 操作日志）
data.js         基础数据（顶部导航、权限项、角色与成员、部门成员）；业务数据已清空
api.js          后端接口封装（登录、会话、个人资料、邮箱服务、状态同步）
xlsx.js         Excel 导入导出
server/
  index.js      HTTP 服务：静态托管 + 接口
  store.js      状态持久化（data/db.json，版本号乐观锁，定时快照）
  auth.js       账号与会话（scrypt 口令、内存令牌、注册 / 新建 / 启停 / 改角色 / 头像 / 邮箱）
  mailer.js     邮件服务（零依赖 SMTP 客户端 + 注册验证码）
  data/         运行时生成：db.json（主库）、accounts.json（账号）、mail.json（邮箱配置）、backups/（快照）
```

## 启动

```powershell
node server/index.js 8080          # 端口可省略，默认 8080
```

打开 http://127.0.0.1:8080/ 即出现登录页。

- 局域网内其他人访问：`http://<你的IP>:8080/`（首次访问需放行防火墙端口：`New-NetFirewallRule -DisplayName "TMPlatform 8080" -Direction Inbound -LocalPort 8080 -Protocol TCP -Action Allow`，管理员 PowerShell）。
- 不要再用 `python -m http.server` 之类纯静态服务：那样只有页面、没有接口，登录会失败。

## 账号体系（管理员 / 注册 / 头像 / 口令）

- **管理员账号（平台唯一预置账号）**：账号名 `admin`，口令 `123456`，角色「最高管理员」，拥有全部权限；首次登录后请立即在头像菜单 →「个人账号设置 → 修改密码」中修改。平台初始化时**只**创建这一个账号，其余账号一律由自助注册或管理员在「设置 → 账号管理」中创建。
- **管理员入口自动兜底**：若账号文件里没有任何可用管理员（被误删 / 全部停用），服务启动时会自动补建 `admin`（角色「最高管理员」、初始口令 123456），避免平台失去管理入口。
- **自助注册（邮箱验证码）**：登录页点「注册新账号」→ 填写邮箱 →「获取验证码」→ 填写 6 位验证码（5 分钟有效，同一邮箱 60 秒内不可重复获取）→ 设置账号（2-20 位，中文 / 字母 / 数字 / `_ . @ -`）与口令（至少 6 位）→ 注册完成后自动回到登录页并预填账号。注册账号默认角色为 **三级**（基础权限），邮箱与账号一一绑定。
  - 邮件发送依赖「设置 → 邮箱服务」中的 SMTP 配置；未配置时注册页会提示「邮箱服务未配置」，此时可先由管理员配置，或在设置页勾选**调试模式**（不发信，验证码直接返回并自动填入）完成本地验证。
- **关闭自助注册**：启动前设置环境变量 `TM_REGISTER=off`（`$env:TM_REGISTER='off'; node server/index.js 8080`）；关闭后注册相关接口返回「平台已关闭自助注册，请联系管理员开通账号」。
- **账号管理**（设置 → 账号管理）：
  - 列表展示账号、邮箱、角色、状态、注册时间、最近登录、来源（平台初始化 / 自助注册 / 管理员）；
  - `＋ 新建账号`：管理员创建账号并指定角色，初始口令由管理员告知本人；
  - `改角色`：调整后立即生效，并同步角色成员表（一人一角色）；
  - `重置`：恢复初始口令 123456，旧口令与在线会话立即失效；
  - `停用 / 启用`：停用后无法登录且在线会话立即失效；`删除`：移除账号与角色成员身份，历史业务数据保留；
  - 安全约束：不能停用 / 删除当前登录账号；至少保留一个可用管理员账号。
- **个人账号设置**（右上角头像菜单）：上传 / 移除头像（自动裁成正方形并压缩到 200×200，存 `accounts.json`）、绑定邮箱、修改口令、退出登录。
- **权限分离**：「设置」页只对**最高管理员**显示入口，其他角色即使勾选「页面访问」也无法进入（导航不渲染、直接访问会被拦回待办页）。导航页签与页面内操作按钮都按权限渲染，无权限的按钮不显示。
- **忘记口令（邮箱自助找回）**：登录页「忘记密码？」→ 填写**账号或绑定邮箱** →「获取验证码」（发到该账号绑定邮箱，5 分钟有效）→ 填写验证码与新口令 → 重置成功后回到登录页，旧会话全部失效。账号未绑定邮箱时需先由管理员在「账号管理 → 重置」恢复 123456。
- 忘记口令（管理员重置）：管理员在「账号管理」里重置；若 `admin` 本身既忘记口令又未绑定邮箱，停止服务 → 删除 `server/data/accounts.json` → 重启（服务重建账号，只有 `admin` 一个，口令恢复为 123456；业务数据不受影响）。
- 会话保存在服务端内存，令牌 12 小时滑动过期；服务重启后需要重新登录。

## 邮箱服务（注册验证码）

「设置 → 邮箱服务」由最高管理员维护，配置保存在 `server/data/mail.json`（权限 600，口令不回显）：

| 字段 | 说明 |
|---|---|
| SMTP 主机 / 端口 | 企业邮箱或第三方发信服务地址，如 `smtp.exmail.qq.com:465` |
| 加密方式 | SSL（通常 465，连接即 TLS）或 STARTTLS（通常 587） |
| 发信账号 / 授权码 | 发信邮箱与客户端授权码（不是登录密码） |
| 发件地址 | 默认同发信账号；可单独指定 |
| 发信人显示名 | 收件人看到的发信人名称 |
| 调试模式 | 不实际发信，验证码直接返回前端并输出到服务端日志；仅用于无 SMTP 环境的联调 |

- 「发送测试邮件」可立即验证配置是否可用（成功 / 失败原因会直接提示）。
- 发信为内置 SMTP 客户端实现（`server/mailer.js`，Node 原生 `net` / `tls`），不依赖额外 npm 包。

## 数据与备份

- 全部业务数据在一个文件里：`server/data/db.json`（含版本号、最后修改人）。
- 每 30 次写入自动快照一份到 `server/data/backups/`，保留最近 20 份；备份/迁移直接拷贝 `server/data/` 整个目录。
- **恢复到空库**：停服务 → 删除 `server/data/db.json` → 重启（账号保留）；或登录后点右上角头像 →「清空数据」。
- 平台不再内置任何演示/测试数据，首次启动为空库，从「产品用例库 → 新建产品」「模块用例库 → 新建功能模块」开始录入。

## 多人协作与保存

- 页面任何写操作先落本机缓存，再以 500ms 防抖推送服务器；保存状态在页面内以提示条 / toast 反馈，断线时提示「离线（本地已保存）」并在恢复后自动补传。
- 保存带版本号做乐观锁：两人同时保存时，后保存的一方会用「本次改动 vs 上次同步快照」做三方合并后自动重试，并提示「已与其他成员同时提交的改动合并」，不会整份覆盖。
- 空闲（无弹窗、无输入焦点）时每 20 秒自动拉取一次最新数据，看到别人刚录的内容不必手动刷新。

## 常见问题

- **端口被占用**：换端口 `node server/index.js 8090`；确认旧进程已退出（`netstat -ano | findstr :8080`）。
- **登录提示无法连接服务器**：服务没启动，或用了纯静态服务打开页面。
- **注册时提示邮箱服务未配置**：先在「设置 → 邮箱服务」填写 SMTP 并保存，或勾选调试模式完成联调。
- **收不到验证码**：检查邮箱服务配置与「发送测试邮件」结果；企业邮箱通常需要使用「客户端授权码」而非登录密码；垃圾邮件箱也看一下。
- **忘记口令**：见上方「忘记口令」。
- **不想暴露后端接口**：服务已禁止下载 `/server/**`（账号口令哈希、主库文件）。
